# Одноразовые напоминания для заметок со звуковыми пресетами

## Цель

Добавить первый сквозной сценарий напоминаний: одна заметка может иметь одно
активное одноразовое напоминание на выбранные дату и время. Напоминание использует
звук, выбранный для этой записи, либо общий звук по умолчанию.

Первый встроенный пресет — двухсекундный фрагмент `Death & Rebirth`. Будущие звуки будут
добавляться как подготовленные встроенные пресеты. Выбор произвольных файлов с телефона
в этот этап не входит.

## Границы первой версии

Входит:

- одно активное одноразовое напоминание на заметку;
- создание, просмотр, изменение и удаление напоминания из редактора заметки;
- общий пресет по умолчанию и персональный выбор для напоминания;
- точный `AlarmManager` с автоматическим переходом на неточный режим, если Android не разрешает
  exact alarm;
- работа при закрытом UI и убитом процессе приложения;
- открытие приложения по нажатию на уведомление.

Не входит:

- повторения, snooze, lead time, quiet hours, escalation и `repeat_until_done`;
- восстановление будильников после перезагрузки телефона, смены часового пояса или обновления APK;
- действия в уведомлении и журнал доставки;
- отдельный экран настроек звука;
- импорт аудиофайлов с телефона.

## Архитектура

### React

В шапке редактора рядом с палитрой появляется кнопка с будильником. Она открывает компактную форму
под шапкой, не меняя остальную композицию экрана. Форма содержит:

- дату;
- время;
- название, предзаполненное заголовком заметки;
- выбор звука;
- действие создания или сохранения;
- действие удаления для уже созданного напоминания.

Кнопки и поля сохраняют минимум 44 px для касания. Активное напоминание показывает дату, время и
фактический звук. Просроченная одноразовая запись не возвращается как активная.

### Rust

Новый доменный модуль `reminders` владеет валидацией, правилом «одна заметка — одно активное напоминание»
и каталогом звуков. `ReminderUseCases` оркестрирует репозиторий и порт `AlarmClock`, но не знает о Tauri или Kotlin.

Основные команды:

- `reminders_get_for_note` — вернуть будущее активное напоминание заметки;
- `reminders_upsert_for_note` — создать или заменить его;
- `reminders_delete_for_note` — отменить системный будильник и мягко удалить запись;
- `reminder_sounds_list` — вернуть валидные пресеты и текущий общий пресет.

Каталог возвращает стабильный ID, подпись для UI и имя Android-ресурса. Имя ресурса состоит только из
`a-z`, `0-9` и `_`. Первый ID — `death_and_rebirth`.

### SQLite

Используются уже существующие таблицы `reminders`, `reminder_occurrences` и `app_settings`; новая миграция не нужна.

- `reminders.sound` хранит `default` или конкретный ID пресета.
- `app_settings['reminders.default_sound']` хранит общий ID. Если ключа ещё нет, Rust использует
  `death_and_rebirth`.
- `reminder_occurrences` хранит конкретное время, стабильный `alarm_request_code` и фактическую точность.

Ограничение «одно активное напоминание на заметку» обеспечивается транзакционным upsert в репозитории.
Схема уже допускает более одной исторической записи, но только одна запись остаётся неудалённой и включённой.

### Android

Звук лежит в `src-tauri/plugins/reminders/android/src/main/res/raw/death_and_rebirth.mp3`. Исходный файл обрезается `ffmpeg`
до первых двух секунд без нормализации громкости.

Каждому конкретному пресету соответствует отдельный `NotificationChannel` с ID вида
`reminders_sound_<sound_id>_v1`. Канал получает URI `android.resource://<package>/raw/<resource_name>` и `AudioAttributes.USAGE_ALARM`.
Это необходимо, потому что на Android 8+ звук уведомления закреплён за каналом.

`ScheduleRequest` дополняется конкретным `soundId`, `soundLabel` и `vibrate`. Android прверяет, что raw-ресурс существует,
создаёт канал до постановки будильника и кладёт ID канала в `PendingIntent`. `ReminderReceiver` публикует уведомление
в этот канал. Ни Kotlin, ни React не выбирают звук сами: они используют уже разрешённый Rust-каталогом ID.

## Поток данных

1. React собирает локальные дату и время, переводит их в UTC-миллисекунды и отдельно передаёт IANA-зону
   устройства.
2. Rust проверяет ID заметки, непустое название, будущее время, часовую зону и ID звука.
3. До записи запрашивается статус Android-разрешений. Если уведомления ещё не разрешены, Android показывает
   системный запрос. При отказе форма остаётся заполненной, а напоминание не создаётся.
4. Репозиторий в транзакции готовит напоминание и одно срабатывание. Стабильный `alarm_request_code` позволяет
   заменять уже поставленный `PendingIntent`.
5. `ReminderUseCases` разрешает `default` в конкретный пресет и вызывает `AlarmClock::schedule`.
6. Android создаёт звуковой канал, ставит будильник и возвращает фактическую точность.
7. Rust сохраняет `is_exact` и завершает транзакцию. Если постановка или commit не удались, Rust вызывает
   `AlarmClock::cancel` как компенсирующее действие и откатывает SQLite.
8. При удалении напоминания или перемещении заметки в корзину системный будильник отменяется, а запись мягко
   удаляется. Архивирование заметки не отменяет напоминание.

## Ошибки и деградация

- Время в прошлом, пустое название, невалидный ID заметки и неизвестный звук отклоняются до вызова Android.
- Отсутствующий raw-ресурс возвращает ошибку платформы. Android не подменяет его другим звуком.
- Отказ в разрешении на уведомления не создаёт невидимый будильник. React показывает понятную ошибку и не очищает форму.
- Запрет exact alarm не блокирует создание: Android использует неточный будильник, SQLite хранит `is_exact = 0`, UI показывает предупреждение о возможной задержке.
- Если Android-вызов или SQLite commit не удались, пользователь получает ошибку, а оба слоя возвращаются в согласованное состояние
  насколько это возможно компенсирующей отменой `AlarmManager`.

## Проверки

### Rust

- валидация будущего времени, звука и заметки;
- создание и обновление одного активного напоминания;
- стабильность `alarm_request_code` при обновлении;
- откат SQLite и компенсирующая отмена при ошибке;
- мягкое удаление и отмена будильника;
- поведение при отказе exact alarm через поддельный `AlarmClock`.

### TypeScript/React

- корректные DTO и вызовы Tauri-команд;
- запрет сохранения прошедшего времени;
- сохранение заполнённой формы при ошибке;
- режимы создания, изменения и удаления;
- предупреждение о неточном будильнике.

### Android

- `cargo check`, Rust-тесты, TypeScript-check и Vitest;
- debug APK с ресурсом `death_and_rebirth`;
- создание и повторное использование звукового `NotificationChannel`;
- проверка на Pixel 8a с погашенным экраном и закрытым UI;
- фактическое звучание двухсекундного пресета;
- поведение при запрещённых уведомлениях и exact alarm.

## Критерии готовности

Функция считается готовой, когда на Pixel 8a можно создать в заметке одноразовое напоминание, закрыть
приложение, дождаться уведомления с выбранным двухсекундным звуком, открыть приложение из уведомления,
затем изменить и удалить напоминание. Основные проверки проходят, а локальное изменение панели форматирования
остаётся незатронутым.
